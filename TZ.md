Техническое задание на проект: gh-scorer

1. Цель проекта
Создание сервиса для оценки надежности Open Source библиотек на GitHub. Система помогает разработчикам принимать решение об использовании библиотеки, анализируя активность репозитория, скорость реакции на issues и актуальность релизов.

2. Роли пользователей
Гость: просмотр списка репозиториев с оценками, добавление новых репозиториев по URL, просмотр детальной аналитики и интерактивных графиков динамики.
Администратор: управление репозиториями и снимками активности через встроенную админ-панель Django.

3. Модели данных
Модель 1: Repository (Репозиторий)
Поля: full_name, url, description, stars, forks, last_commit_date, last_release_date, created_at, updated_at.
Модель 2: ActivitySnapshot (Снимок активности)
Поля: repository (связь ForeignKey), snapshot_date, commits_last_30_days, open_issues_count, avg_issue_close_days, contributors_count.
Модель 3: ReliabilityScore (Оценка надежности)
Поля: repository (связь ForeignKey), snapshot (связь ForeignKey), total_score, commit_score, issues_score, release_score, community_score, calculated_at.

4. Ключевой функционал
* Пользователь открывает главную страницу и видит список репозиториев с их оценкой надежности, может отсортировать по оценке или звездам.
* Пользователь вводит URL GitHub-репозитория в форму — система проверяет существование репозитория через GitHub REST API, подтягивает данные и рассчитывает оценку.
* Пользователь открывает детальную страницу репозитория — видит разбор оценки по компонентам и интерактивный график динамики (Plotly).
* Пользователь нажимает кнопку «Обновить данные» — система запрашивает свежие данные из GitHub REST API и пересчитывает оценку.

5. Внешние интеграции и аналитика
Интеграция: Использование GitHub REST API для получения данных о репозиториях (коммиты, issues, звезды, релизы).
Аналитика: Использование библиотеки Pandas для агрегации метрик и расчета средних значений. Построение интерактивных графиков через Plotly.

8. Изменения в ходе реализации
* Реализован поиск репозиториев на главной странице по названию и описанию.
* На детальную страницу добавлена таблица с расширенной информацией: дата проверки, количество коммитов за 30 дней, открытые issues, среднее время закрытия, контрибьюторы, последний релиз.
* В модели ReliabilityScore связь repository изменена с OneToOneField на ForeignKey для хранения истории оценок и построения графика динамики.
